## V1 완료 — 2026-11-19

V1은 단일표적 HIL의 기준 버전입니다. 단일표적 측정 입력부터 보드 추적, PC 결과 수신·정량 평가까지 연결하고, 주요 오류 복구와 30분 부하의 시간·자원을 확인한 범위로 마무리합니다. 아래 수치는 저장된 시험 기록을 사용하며 이번 문서 정리에서 새로운 실보드 시험을 수행하지 않았습니다.

### 송수신·자원 기준선

STM32F746G-DISCO / Zephyr 4.2, `perf.conf`·DRAIN, 115200/8N1, 정지 단일표적·잡음 0. 목표 MEAS 50Hz + STATUS 1Hz, 1,800초 실행입니다.

| 지표 | 관측값 |
| --- | ---: |
| 측정 송신·대응 수신 | 각 89,990건 |
| 실제 평균 송신률 | 49.994Hz |
| PC RTT p50 / p95 / p99 / 최대 | 6.386 / 6.633 / 8.049 / 34.894ms |
| 보드 RX 완료 → TX 큐 제출 최대 / 20ms 초과 | 1ms / 0건 |
| TRACK / STATUS 수신 | 89,992 / 1,801건 |
| TX 큐 접수 / polling 완료 / PC 수신 | 각 91,793프레임 |
| RX / TX 큐 거부 | 각 0건 |
| RX / handler / TX 스택 최소 잔여 관측값 | 784 / 1,472 / 736B |
| perf 빌드 FLASH / RAM | 44,604 / 16,464B |

TRACK에는 측정 응답 외 INIT·무수신 timeout 이벤트 2건이 포함됩니다. 스택·큐 점유는 관측값이며 전체 실행의 엄밀한 최악값을 보장하지 않습니다. [집계 원본](test-results/perf-counter-load-2026-11-19/offline-audit.json).

### 판정 변경과 측정 경계

- PC 송신 간격은 OS 스케줄링·프로세스 부하·I/O 대기 등 호스트 영향을 받습니다. STM32 성능의 독립적인 판정 기준에서 제외하고 실제 송신률·최대 간격·건너뛴 슬롯을 참고 통계로 유지합니다.
- 주 성능 지표는 **PC write 직전 → 대응 TRACK이 포함된 read 직후**의 왕복 지연입니다. 기본 기준은 **p99 ≤20ms, 최대 ≤100ms**이며 위 시험 관측값은 두 기준 이내입니다. 호스트·USB·UART도 포함하므로 MCU만의 처리시간으로 해석하지 않습니다.
- 보드 RX 완료 → TX 큐 제출 예산 20ms, 응답 대응·순번·오류·폐기·스택 검사도 유지합니다. UART 전송 완료까지의 지연은 보드 내부 수치에 포함되지 않습니다.
- 11월 19일 원본 실행은 당시 호스트 송신 간격 137.581ms 때문에 실패했습니다. 원본 판정을 바꾸지 않고 현재 기준의 해석을 구분합니다. 11월 18일 실행의 RTT 최대 164.128ms는 현재 100ms 기준에도 미달하므로 모든 과거 실행을 일괄 통과로 바꾸지 않습니다.
- 고정 방위각·각도 잡음 0에서의 평가입니다. 각도 기동·잡음, 실제 센서, 최대 지속 부하, WCET·실운용 성능을 증명한 것은 아닙니다. 정상 부하와 의도적인 오류 주입의 결과는 각각의 기록 범위로 읽습니다.

위 V1 기준선과 별도로, 후속 [잡음100회·순간 이상치49회 실보드 평가](hardware-test-2026-11-19-noise-spike.md)를 완료했습니다. 고정 방위각의 각도 잡음과 주입 후 복귀를 확인했으며 각도 기동·동시 양축 잡음은 추가 범위입니다.

## 다음 구현 순서

V1은 종료하고 결함 수정·재현성 유지에 집중합니다. 아래 항목은 V1을 다시 미완료로 만드는 필수 작업이 아니라, 필요할 때 별도 요구사항과 시험 범위를 정할 후속 후보입니다.

| 영역 | 후속 후보 |
| --- | --- |
| 지연 최적화 | PC 수신·동기 기록·콘솔 비용, TX 큐 대기·전송 계측과 같은 조건의 RTT 전후 비교 |
| 추적 확장 | 다중표적 입력 묶음·스캔 경계·상한, 측정 연관·트랙 테이블·자체 ID·수명 관리, 교차·클러터·재등장 평가 |
| 모델 비교 | CT/IMM/EKF·adaptive gating, 각도 기동·동시 양축 잡음 시나리오 |
| 제어·송신 정책 | INIT/RESET 우선 보존·전용 ACK·reset 이전 큐 폐기, TX 포화 시 보고별 우선순위, 이벤트 원인·상시 TX 진단 규격 |
| 추가 장애 시험 | UART overrun/framing/parity 감지·집계·복구, DISCARD 전체 행렬, 실제 동시 조회·USB 제거·전원 재인가 |
| 로그·부하 | 반복 경고 제한, 최대 지속 부하와 UART 영향 |
| 기능·하드웨어 | BIT·COMMAND/Lock On·LCD, DMA·새 버스·PCB·새 보드 |

스레드는 표적 수가 아니라 독립 실행 요구에 따라 추가합니다. PC 정답 target ID는 측정 입력으로 넘기지 않습니다. [역할·ID 정책](system-roles.md).
