# 시스템 역할과 추적 경계

## 결정

이 프로젝트는 **추적 전 레이더 탐지 측정을 입력받는 표적 추적기**를 구현한다.
PC 시뮬레이터는 레이더의 탐지 측정 출력 인터페이스를 모사하고,
STM32/Zephyr 펌웨어는 해당 측정을 받아 추적하는 컴퓨터 역할을 맡는다.
이미 추적을 완료한 레이더가 안정적인 target ID와 추정 상태를 보내는
트랙 입력 시스템을 현재 프로젝트의 기준으로 삼지 않는다.

```text
PC: 합성 표적 운동과 정답 상태
  → 센서 모델: 잡음·미탐지·클러터가 포함된 탐지 측정
  → UART: 시간·거리·방위각 (표적 정답 ID 없음)
STM32: 프레임 검증
  → 예측·게이팅·측정-트랙 연관
  → 필터 갱신·트랙 생성/유지/삭제·track_id 부여
  → 향후 추적 결과 출력
PC: 향후 정답과 보드 결과를 비교해 오차·트랙 연속성 평가
```

위 흐름은 목표 구조이다. 다중표적 연관, 다중 트랙 ID 관리, 이진 추적 결과 반환과
폐루프 평가는 아직 구현되지 않았다.

## 구성별 책임

| 구성 | 담당 | 범위 밖 또는 미구현 |
| --- | --- | --- |
| PC 시뮬레이터 | 합성 표적 운동, 센서 측정 생성, 시험 시나리오와 송신 | 실제 RF·ADC/IQ·FFT·탐지 신호처리 구현은 범위 밖 |
| STM32 펌웨어 | 측정 해석, 예측, 게이팅, 칼만 필터, 트랙 상태 관리 | 다중 측정 연관과 다중 트랙 관리는 향후 구현 |
| PC GUI | 시험 설정·송신 제어, PC 합성값 그래프, ST-Link 로그 | 현재 보드 추정값 그래프·운용 제어 화면은 미구현 |

STM32는 레이더 전체를 제어하는 완성된 메인 컴퓨터가 아니라,
탐지 측정 이후의 추적 처리를 학습·검증하는 프로토타입이다.
실제 장비에서 이 추적기가 레이더 내부에 있는지 별도 컴퓨터에 있는지는
이 프로젝트의 기능 경계와 별개다.

## ID와 데이터 경계

- PC의 `Target.target_id`는 합성 정답 표적을 구분하는 내부 식별자다.
  현재 `Measurement`와 10바이트 UART 측정 payload에는 포함되지 않는다.
- PC는 어떤 탐지점이 어느 실제 표적에서 나왔는지 알려 주는 지속적인 ID를
  펌웨어 측정 입력에 추가하지 않는다. 정답 ID는 향후 PC 평가용으로만 사용한다.
- 펌웨어의 `track_id`는 펌웨어가 트랙을 생성할 때 부여할 식별자이며,
  PC 정답 ID와 같을 필요가 없다. 현재 다중 트랙 ID 체계는 미구현이다.
- 향후 `scan_id`나 스캔 내부 측정 번호가 필요하면 전송·묶음 구분에 사용한다.
  이를 시간에 걸쳐 동일 표적을 식별하는 정답 ID로 사용하지 않는다.
- 다중표적 연관은 수신 순서나 PC 정답을 이용하지 않고 측정·예측 상태로 판단한다.

안정적인 표적 ID와 추정 상태를 제공하는 레이더의 트랙 출력을 받으면,
상위 컴퓨터의 중심 역할은 트랙 수신·관리·표시·융합이 된다.
그 구조는 여기서 직접 구현하려는 탐지점 기반 추적기와 입력 경계가 다르다.
상위 필터링이 가능한지와는 별개로, 본 프로젝트에서는 정답 연관을 입력으로 제공하지 않는다.

## 현재 구현과 다음 확장

현재 wire 측정은 `timestamp_ms + range_m + azimuth_sc`이며, 단일 트랙에 대해
칼만 예측·게이팅·갱신과 timeout을 수행한다. 현재 게이팅은 한 트랙에 대한
측정 수용 여부 검사이며, 여러 후보 중 대응 트랙을 고르는 연관 알고리즘은 아니다.
PC 다중표적·클러터 시나리오는 출력 전용이고 실제 UART 송신은 단일표적으로 제한한다.

다중표적 확장 시에는 스캔 경계, 여러 탐지점과 트랙의 연관,
미연관 측정의 트랙 생성, 미연관 트랙의 유지·삭제, 펌웨어 자체 ID 관리를 함께 설계한다.
측정 payload에 정답 `target_id`를 추가해서 연관 문제를 우회하지 않는다.
