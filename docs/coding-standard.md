# 펌웨어 코딩 스탠다드 초안

2026-11-08 합의한 목표 규칙입니다. 기존 코드 전체에 적용된 상태는 아니며,
펌웨어 작성자가 이후 리팩터링합니다. 현재 동작·프로토콜 숫자 값은 보존합니다.

## 이름

| 대상 | 규칙 | 예시 |
|---|---|---|
| 함수·일반 변수·구조체 태그 | snake_case | `protocol_frame_encode`, `payload_length`, `struct protocol_frame` |
| 입력·참조 포인터 | `p_` 접두사 | `const struct protocol_frame *p_frame` |
| 결과를 기록하는 출력 포인터 | `out_` 접두사 | `uint8_t *out_buffer`, `size_t *out_length` |
| enum 타입 | PascalCase, 약어도 단어처럼 표기 | `FrameType`, `ParserState`, `RxOverflowPolicy` |
| enum 열거자 | enum 타입명을 UPPER_SNAKE_CASE로 변환한 접두사 + 항목명 | `FRAME_TYPE_INIT`, `PARSER_STATE_WAIT_STX`, `RX_OVERFLOW_POLICY_DRAIN_BUFFER` |
| 매크로·상수 | UPPER_SNAKE_CASE, 모듈 접두사 권장 | `PROTOCOL_FRAME_OVERHEAD`, `CRC16_INITIAL_VALUE` |

출력 포인터에는 `p_`를 중복하지 않고 `out_`만 사용합니다.
포인터가 가리키는 상태 객체를 갱신하는 것과 별도 결과를 출력하는 것은 구분합니다.
예를 들어 `parser_feed(struct frame_parser *p_parser, ...)`는 상태 객체 참조이고,
디코더의 `struct radar_measurement *out_measurement`는 결과 출력입니다.
읽기 전용 입력에는 가능한 경우 `const`를 붙입니다.
배열로 선언한 지역 송신 버퍼는 일반 변수이며 `buffer`처럼 표기합니다.
헤더 선언과 구현의 매개변수 이름도 일치시킵니다.

## 중괄호와 공백

함수의 여는 중괄호는 다음 줄에 둡니다. 제어문의 여는 중괄호는 같은 줄에 둡니다.
`if`, `for`, `while`, `switch`와 여는 괄호 사이에는 공백 한 칸을 둡니다.
들여쓰기는 공백 4칸이며, 줄 끝 공백을 제거하고 파일 끝에 개행을 둡니다.

```c
int example(const struct protocol_frame *p_frame, uint8_t *out_buffer)
{
    if (p_frame == NULL || out_buffer == NULL) {
        return -EINVAL;
    }

    for (size_t i = 0; i < p_frame->payload_length; ++i) {
        out_buffer[i] = p_frame->payload[i];
    }

    return 0;
}
```

위 코드는 표기 예시이며 실제 복사 API에는 출력 용량 검증도 필요합니다.

## 오류 반환

실패를 반환하는 API는 `<errno.h>`의 오류 코드를 음수로 반환합니다.
별도의 `ERROR_*` 상수나 프로젝트 오류 enum은 만들지 않습니다.
임의의 `-1`은 의미가 드러나는 errno로 정리합니다.

| 반환값 | 의미와 적용 예 |
|---|---|
| `0` | 일반 상태 반환 API 성공, 예: init·큐 제출 |
| `-EINVAL` | NULL 인자·잘못된 payload 길이 |
| `-ENOSPC` | 인코더 출력 버퍼 용량 부족 |
| `-ENOMSG` | 현재 `k_msgq_put(..., K_NO_WAIT)`에서 큐 포화 |
| `-ENODEV` | 사용할 장치가 준비되지 않음 |

Zephyr API에서 받은 오류는 의미가 맞으면 원래 음수 errno를 그대로 전달합니다.
호출부는 문서화된 errno별로 처리하고, 큐 포화와 잘못된 인자를 별도 집계합니다.
예상하지 못한 음수 오류는 원래 코드와 함께 진단합니다.
인코더처럼 성공 시 바이트 수를 반환하는 함수는 비음수 성공 값과 음수 오류를 구분하고,
이 반환 계약을 헤더에 명시합니다. errno는 호출의 반환값으로 전달하며 전역
`errno` 변수를 설정하는 방식과 혼동하지 않습니다.

`bool` 판정 함수와 `ParserResult` 같은 처리 결과 enum까지 기계적으로 변환하지 않습니다.
조립 중·완성·CRC 오류 등 상태 머신 결과는 해당 enum으로 표현합니다.

이 문서 추가만으로 기존 반환값 계약을 바꾸지 않습니다.
초기화 함수의 `-1` 등을 정리할 때 선언·구현·호출부·통계·테스트를 함께 확인합니다.

## 헤더·규격·주석

- 헤더는 단독 include가 가능해야 합니다. `size_t`는 `<stddef.h>` 등 필요한 타입 헤더를 직접 포함합니다.
- 구현은 사용하는 함수의 헤더를 직접 포함합니다. 예: `memcpy`는 `<string.h>`.
- STX·프레임 추가 길이 등 공유 규격은 공통 헤더 한 곳에 정의합니다.
- 주석은 영어 또는 영어·한국어 병기를 사용합니다.
- 공개 함수에는 입력 유효성 전제·버퍼 용량·반환값·데이터 복사/소유권을 설명합니다.
- 주석은 실제 IRQ 보호 범위와 스레드 책임에 맞춥니다.

## 모듈 경계와 상태 소유권

- 외부에서 호출할 함수·공유 타입만 헤더에 공개하고 내부 함수·파일 상태는 `static`으로 제한합니다.
- 한 상태의 갱신 책임을 명확히 합니다. 현재 parser는 RX 스레드, track은 handler 스레드,
  UART 송신은 TX 스레드가 담당합니다. 다른 스레드는 큐나 명시적인 조회 API를 사용합니다.
- CRC 알고리즘은 UART·파서에 의존하지 않고, 프로토콜 인코더는 Zephyr 장치에 의존하지 않습니다.
  공통화는 실제로 같은 데이터·검증 규칙부터 하며, 한 줄을 줄이기 위한 `void *` 래퍼는 피합니다.
- 구조체 정의를 사용하는 함수 선언보다 앞에 배치하거나 명시적으로 전방 선언합니다.
- `.c`의 첫 include는 가능하면 자신의 공개 헤더로 두어 누락된 헤더 의존성을 발견합니다.
  이후 표준 C·Zephyr·프로젝트 헤더를 그룹으로 구분합니다.

## 포인터·버퍼·큐 계약

- 공개 제출 API와 외부 데이터 경계에서 NULL·길이·용량을 검사합니다.
  이미 검증된 내부 함수는 같은 검사를 무조건 반복하지 않고 유효 입력 전제를 명시합니다.
- 버퍼 길이와 용량은 바이트 단위를 명시합니다. 복사·인코딩 전에 필요한 크기를 확인합니다.
- 실패 시 출력 버퍼가 유지되는지, 일부 결과가 남을 수 있는지 API 계약에 적습니다.
  현재 인코더는 입력·용량 오류 시 아무 바이트도 기록하지 않는 동작을 유지합니다.
- `k_msgq_put()`은 큐 항목을 복사합니다. 항목에 포인터를 넣으면 가리키는 데이터까지
  복사되는 것은 아니므로, 지역변수 주소를 수명 관리 없이 비동기 큐에 넘기지 않습니다.
- 큐 제출 성공과 실제 처리·송신 완료를 구분합니다. `uart_tx_submit()`의 성공을
  PC 수신 성공이나 UART 송신 완료로 표현하지 않습니다.
- 큐 크기·포화 시 폐기/대기 정책·호출 가능한 문맥을 문서화합니다.
  처리 스레드의 현재 submit API는 `K_NO_WAIT` 정책을 유지합니다.

## 타입·단위·직렬화

- wire 필드에는 고정 폭 정수 타입을 사용하고, 메모리 버퍼 크기·인덱스에는
  범위에 맞는 타입을 사용합니다. 일반 버퍼 크기는 `size_t`, 오류 반환은 `int`를 사용합니다.
- `uint8_t` 링 인덱스처럼 의도적으로 작은 타입을 사용하면 최대 버퍼 크기 제약을
  문서화하고 정적 검증으로 지킵니다. 버퍼 크기 변경 시 인덱스 범위도 함께 확인합니다.
- 축소 변환·부호 변환은 범위를 확인한 뒤 수행합니다. 명시적 cast만으로 검증을 대신하지 않습니다.
- enum·구조체 메모리를 그대로 전송하지 않습니다. 각 wire 필드의 폭·바이트 순서·길이를
  명시하여 인코딩하고, CRC 범위와 CRC 바이트 순서도 프로토콜 규격 한 곳에서 정의합니다.
- 물리량과 시각은 `_ms`, `_s`, `_m`, `_rad` 등 단위를 이름에 표시합니다.
  필터 잡음·분산 상수는 단위와 산출 근거를 주석으로 남깁니다.
- 필터의 `float` 상수는 `0.0f`처럼 타입을 명시합니다. 변경하지 않는 지역 계산 결과에는
  `const`를 사용해 재대입 의도가 없음을 드러냅니다.

## Assert 사용 권장

- 컴파일 시 결정되는 불변조건은 **정적 assert 사용을 권장**합니다. 디버그·릴리스 모두 유지합니다.
  예: 링버퍼 크기와 인덱스 범위, payload 최대 길이와 wire 길이 필드의 표현 범위.
  Zephyr 독립 C 모듈은 C11 `_Static_assert`, Zephyr 전용 모듈은 `BUILD_ASSERT`를 사용할 수 있습니다.
- **런타임 assert도 내부 불변조건 검증에 권장**하되, 펌웨어에서는 디버그 빌드에서만 활성화합니다.
  예: 검증을 마친 내부 경로의 인덱스 범위, 내부 함수의 필수 상태 객체, 도달해서는 안 되는 상태.
  모든 함수에 기계적으로 추가하지 않고 위반 시 프로그래밍 오류인 조건에 사용합니다.
- UART 입력의 CRC·길이 오류, 큐 포화, 장치 미준비, timeout 등 예상 가능한 운영 오류는
  assert로 처리하지 않습니다. 외부 입력 검증과 공개 API의 오류 반환·복구는 릴리스에도 유지합니다.
- assert 조건식에는 대입·증가·큐 제출·함수의 필수 동작 등 부작용을 넣지 않습니다.
  assert가 제거돼도 정상 동작과 오류 처리가 같아야 합니다.
- Zephyr 런타임 assert는 `__ASSERT` 계열과 `CONFIG_ASSERT` 설정으로 관리합니다.
  표준 C `assert()`는 `<assert.h>`와 `NDEBUG`로 관리하며, 두 설정을 같은 스위치로 간주하지 않습니다.
  디버그/릴리스 빌드 설정을 분리할 때 실제 활성 여부를 각각 확인합니다.
- 이 디버그 전용 규칙은 **제품 펌웨어의 런타임 진단**에 적용합니다.
  host 테스트의 판정용 assert는 Release 테스트에서도 활성화해 검증이 사라지지 않게 합니다.

```c
_Static_assert(BUFFER_SIZE >= 2 && BUFFER_SIZE <= 256,
               "BUFFER_SIZE must be between 2 and 256");
```

이 절은 적용 목표입니다. 문서 추가만으로 코드나 빌드 설정을 변경한 것은 아닙니다.

## 시간과 초기화

- 송신 장비의 측정 timestamp와 보드 uptime을 혼용해 차감하지 않습니다.
  수신 시각·처리 시각·송신 시각은 실제 측정한 시점을 주석에 적습니다.
- timeout은 기준 시각·단위·만료 경계(`>=` 등)·감시 시작/해제 조건을 명시합니다.
  `uint32_t` timestamp의 wraparound는 정의된 차이 계산 규칙과 경계 테스트로 다룹니다.
- init/reset이 지우는 상태와 보존하는 누적 통계를 구분합니다.
  카운터 초기화가 필요하면 기존 parser/track reset에 암묵적으로 섞지 않습니다.
- 소비 스레드는 필요한 초기화 완료 후 동작하게 합니다. init의 중복 호출 허용 여부와
  초기화 실패 시 submit 동작을 정하고, 재초기화가 대기 큐에 주는 영향을 명시합니다.

## ISR·동기화·실시간 경로

- ISR은 바이트 이동·최소 상태 갱신·스레드 알림에 집중합니다.
  대기 가능한 API·polling 송신·추적 계산·대량 로그를 ISR에 넣지 않습니다.
- IRQ 잠금 구간은 공유 상태 접근에 필요한 최소 범위로 한정합니다.
  잠금 중 블로킹 송신·CRC 계산·로그를 수행하지 않고 모든 경로에서 원래 키로 해제합니다.
- `volatile`을 동기화 수단으로 취급하지 않습니다. 공유 접근은 소유 스레드,
  atomic, IRQ 보호 등 실제 접근 문맥에 맞는 방법으로 보호합니다.
- atomic 카운터 각각을 읽는 것과 여러 필드를 같은 시점에 읽는 것을 구분합니다.
  현재 stats 조회는 개별 값의 안전한 읽기이며 전체 동시 snapshot은 아닙니다.
- 큐 대기는 스레드 동기화를 담당하므로 같은 목적의 알림 세마포어를 중복하지 않습니다.
  초기화 완료 세마포어는 별도 역할로 유지합니다.
- 크기가 가변인 스택 배열이나 큰 지역 버퍼를 추가하기 전에 최대 크기와 스택 사용량을 검토합니다.
  블로킹 API를 선택하면 대기 범위·timeout 지원 여부를 명시하고 ISR에서 호출하지 않습니다.

## 분기·로그·테스트

- `if`·`for`·`while` 본문은 한 문장이더라도 중괄호를 사용합니다.
  `switch`의 case는 switch와 같은 들여쓰기에 두고, 지역변수가 필요한 case는 `{ ... }`로 감쌉니다.
- 의도적인 case fallthrough에는 `/* Intentional fallthrough. */` 주석이나
  프로젝트에서 지원하는 fallthrough 표기를 사용합니다.
- 반환값을 무시할 때는 이유가 드러나게 합니다. 예를 들어 주기적 timeout 검사를 위한
  세마포어 대기 만료는 예상 흐름이며, 오류를 이유 없이 모두 성공처럼 처리하지 않습니다.
- 로그에는 실패한 작업·원인 코드·필요한 값만 포함하고 바이트별 로그는 피합니다.
  반복 오류는 집계·출력 제한을 검토하며, 내부 요청 오류와 외부 CRC 오류를 혼합 집계하지 않습니다.
- `TODO`는 단순히 “처리 필요”라고 쓰기보다 빠진 동작·완료 조건을 적습니다.
- 공개 구조체·함수·소스 파일 분리 시 CMake, host fixture, Python의 C 래퍼와 문서를 함께 갱신합니다.
- 프로토콜 변경은 PC 인코더/디코더와 함께 검증합니다. 정상값 외에 최소·최대·용량 부족·
  잘못된 입력·CRC 손상·오류 후 복귀를 실제 변경 범위에 맞게 시험합니다.
- host 테스트·펌웨어 빌드·flash·실보드 결과를 구분해서 기록합니다.
  모사 큐·atomic·UART 테스트를 실제 동시성이나 물리 전송 성공의 증거로 사용하지 않습니다.
